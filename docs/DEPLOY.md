# Deploying CIP: Supabase + Render + Vercel

```
 Browser ──▶ Vercel (React static site, CDN)
    │
    └──── /api/* (CORS) ──▶ Render web service (FastAPI + outbox relay/consumer workers, Docker)
                                 │
                                 ├──▶ Supabase Postgres   (tables, triggers, pgcrypto, outbox)
                                 └──▶ Supabase Storage    (private bucket: source / derived / staging blobs)
```

| Piece | Where | Why there |
|---|---|---|
| React UI | **Vercel** | Static files on a global CDN, preview deploys per branch |
| FastAPI + workers | **Render** (Docker web service) | Long-running process: the outbox relay and consumers run in a background thread; uploads up to 25 MB |
| PostgreSQL 16 | **Supabase** | Managed Postgres with `pgcrypto`; triggers and `SKIP LOCKED` work unchanged |
| Document files | **Supabase Storage** | Render's disk is wiped on every deploy/restart |

> **PHI.** The demo seeds 40 *synthetic* cases. Before any real patient data: sign a HIPAA BAA
> with Supabase, Render and Vercel (paid plans), set `CIP_SEED_DEMO_DATA=false`, and add
> authentication. The app has no login yet — roles are passed in requests for demo purposes.

Put the code in a GitHub (or GitLab) repository first; Render and Vercel deploy from it.
Use **one region** for Supabase and Render (the blueprint uses `singapore`; pick Supabase
*Southeast Asia (Singapore)*, or change both).

---

## 1. Supabase (database + storage)

1. <https://supabase.com/dashboard> → **New project**. Choose the region, set a strong database
   password and keep it.
2. **Connect** (top bar) → **Session pooler** → copy the URI. It looks like
   `postgresql://postgres.<ref>:[YOUR-PASSWORD]@aws-0-ap-southeast-1.pooler.supabase.com:5432/postgres`.
   Replace `[YOUR-PASSWORD]`. This is `CIP_DATABASE_URL`.
   - Use the **session** pooler (port 5432). It works over IPv4, which Render needs.
     The transaction pooler (6543) also works, but session mode is the safer default.
   - Paste it as-is: the app adds the `+psycopg` driver and `sslmode=require` itself.
3. Copy the **Project URL** (`CIP_SUPABASE_URL`, e.g. `https://<ref>.supabase.co`) and a
   **secret** key (`CIP_SUPABASE_SERVICE_ROLE_KEY`): **Project Settings → API Keys → Secret keys**
   (`sb_secret_…`), or the legacy **service_role** key (`eyJ…`); both work. **Not** the
   publishable key (`sb_publishable_…`): it can't reach the private bucket. The secret key
   bypasses all security: it goes only into Render, never into Vercel or the browser.
4. Nothing else to create. On first start the API creates the tables, triggers, the
   `dcn_seq` sequence, the private `cip-documents` bucket, and turns **Row Level Security on
   for every table** so the public Data API (anon key) can't read the PHI tables.
   Optional, stricter: **Project Settings → Data API** → turn the Data API off; CIP doesn't use it.

## 2. Render (API)

1. <https://dashboard.render.com> → **New → Blueprint** → connect the repository. Render reads
   [`render.yaml`](../render.yaml) and proposes the `cip-api` web service.
2. Fill in the secrets it asks for:

   | Variable | Value |
   |---|---|
   | `CIP_DATABASE_URL` | Supabase session-pooler URI from step 1.2 |
   | `CIP_SUPABASE_URL` | `https://<ref>.supabase.co` |
   | `CIP_SUPABASE_SERVICE_ROLE_KEY` | service_role key |
   | `CIP_CORS_ORIGINS` | `[]` for now. You'll set the Vercel URL in step 4 |
   | `CIP_CORS_ORIGIN_REGEX` | leave empty (optional, see step 4) |

   `CIP_FIELD_ENCRYPTION_KEY` is generated by Render. **Copy it to a password manager**: if it's
   lost or changed, the encrypted member names, dates of birth and addresses can't be decrypted.
3. **Apply**. The first deploy builds the Docker image, creates the schema and seeds the demo data
   (about a minute). Check `https://cip-api-xxxx.onrender.com/api/health` → `{"status":"ok",...}`.
   Swagger is at `/docs`.
4. Note the service URL (e.g. `https://cip-api.onrender.com`). Vercel needs it.

Plan: the blueprint uses **Starter** (always on). The free plan works for a quick look, but it
sleeps after 15 minutes idle, so the first request takes ~1 minute and the background workers
stop while it sleeps.

## 3. Vercel (UI)

1. <https://vercel.com/new> → import the repository.
2. **Root Directory**: `frontend`. Vercel picks up [`frontend/vercel.json`](../frontend/vercel.json)
   (Vite build, `dist/` output, SPA routing, security headers).
3. **Environment Variables** → add `VITE_API_BASE_URL` = the Render URL from step 2.4, without a
   trailing slash, for *Production* (and *Preview* if you use previews). It is compiled into the
   bundle, so **redeploy after changing it**.
4. **Deploy**, then note the production URL (e.g. `https://cip-console.vercel.app`).

## 4. Connect them (CORS)

In Render → `cip-api` → **Environment**:

- `CIP_CORS_ORIGINS` = `["https://cip-console.vercel.app"]` (JSON list; add a custom domain too
  if you attach one).
- Optional, to let Vercel *preview* deployments call the API:
  `CIP_CORS_ORIGIN_REGEX` = `^https://cip-console-[a-z0-9-]+\.vercel\.app$`
  (replace `cip-console` with your Vercel project name).

Save. Render redeploys. Open the Vercel URL: the dashboard should load with the demo data and the
sidebar should show **API online**.

## 5. Check it works

1. **Dashboard** shows KPIs (data came from Supabase through Render).
2. **Upload Documents** → upload `docs/sample-documents/scenarios/case5_appeal_ct_head_urgent.pdf`
   → step through → **Submit** → you get a DCN. In Supabase → **Storage → cip-documents** the file
   appears under `source/…`.
3. **WIP Pipeline** → the new DCN moves to *In review* within a few seconds (workers running).

## Differences from local

- **Simulate tampering** on *Classify & Extract* is disabled outside `CIP_ENVIRONMENT=local`
  (HTTP 403), by design. The seeded quarantined case still demonstrates detection.
- Each restart re-runs the idempotent schema bootstrap; demo data is seeded only into an empty
  database.

## Troubleshooting

| Symptom | Cause / fix |
|---|---|
| Render deploy fails at start with `could not translate host name` or `Network is unreachable` | You used the *direct* connection (`db.<ref>.supabase.co`, IPv6-only). Use the **session pooler** URI. |
| `password authentication failed` | `[YOUR-PASSWORD]` still in the URI, or the user isn't `postgres.<ref>` for the pooler. |
| `CIP_STORAGE_BACKEND=supabase needs CIP_SUPABASE_URL…` | Storage secrets missing on Render. |
| UI loads but every call fails, browser console shows a CORS error | `CIP_CORS_ORIGINS` doesn't contain the exact Vercel origin (scheme + host, no trailing slash). |
| UI calls `https://<vercel-domain>/api/...` and gets 404 | `VITE_API_BASE_URL` not set when Vercel built it. Set it and redeploy. |
| `remaining connection slots are reserved` | Lower `CIP_DB_POOL_SIZE` / `CIP_DB_MAX_OVERFLOW`, or upgrade the Supabase compute size. |
